# Peer Score Finder — 2027학년도 모집요강 DB 적재 & 코드 개선 가이드

## 1. 시스템 및 DB 핵심 구조

### ① 테이블 구조 (`TiDB / MySQL`)
* **`recruit_quota` (모집요강 테이블)**
  * 주요 컬럼: `id`, `year` (현재 기준 `2026`으로 적재), `univ`, `department` (`인문` / `자연`), `major`, `general_quota`, `bachelor_quota`
  * **0명 학과 유지 원칙**: 일반정원과 학사정원이 모두 `0`인 미모집·특별전형 전용·개편 전 과거 학과도 과거 합격생 연결과 UI 분리를 위해 누락하지 않고 적재합니다.
* **`peer_data` (과거 합격생 성적 테이블)**
  * 주요 컬럼: `student_name`, `univ`, `department` (`일반인문`, `일반자연`, `학사인문`, `학사자연`), `major`, `year`

### ② 자동 매칭 정규화 규칙 (`clean_major_name`)
백엔드에서 `recruit_quota.major`와 `peer_data.major`를 비교할 때 아래 3단계 정규화를 거쳐 핵심 키워드(코어) 일치 여부를 판정합니다.
1. **앞쪽 학부명 접두어 제거**: `^.+?학부\s+(.+)` 패턴 적용 (가운뎃점 `·`이나 공백이 포함된 `첨단소재·전자융합공학부 신소재물리전공`, `Fine Arts학부 서양화전공` 등 포함, 단독 명칭인 `법학부`·`경영학부`는 유지)
2. **특수기호 및 공백 제거**: `*`, `·`, `•`, `ㆍ`, `(`, `)`, `[`, `]`, `/`, `-`, 공백 제거
3. **끝부분 접미어 일관 제거**: `(학전공|공학전공|공학과|학과|학부|전공|과)` 제거 후 핵심어 비교

## 2. 파이참(JetBrains Air)용 코드 수정 프롬프트

### ① 1단계: 프로젝트 분석 및 수정 계획 요청 프롬프트
> 파이참 AI 채팅창(에이전트 모드)에 붙여넣어 기존 백엔드(`backend/main.py`)와 프론트엔드(`ApplicationStrategy.vue`)를 직접 수정하도록 요청하는 프롬프트입니다.

```text
현재 워크스페이스의 편입 상담 웹앱(`Peer Score Finder` — FastAPI 백엔드 + Vue.js 프론트엔드 + MySQL/TiDB) 코드를 분석해서, 불필요한 새 파일을 만들지 말고 **기존 파일들을 직접 수정**해 줘.

지금까지 대학별 2027학년도 모집요강을 DB에 올리면서 반복적으로 겪은 데이터 매칭·캐시·UI 문제를 코드 레벨에서 근본적으로 해결하려고 해.

### 1. 현재 DB 테이블 구조 (수정 금지, 기존 스키마 유지)
- **`recruit_quota` (모집요강 테이블)**
  - 주요 컬럼: `id`, `year`(현재 기준 `2026`으로 적재), `univ`, `department`(`인문`, `자연`), `major`, `general_quota`, `bachelor_quota`
  - **중요 규칙**: 일반정원(`general_quota`)과 학사정원(`bachelor_quota`)이 모두 `0`인 학과(올해 미모집 또는 개편 전 과거 학과)도 과거 합격생 연결을 위해 DB에 그대로 유지함.
- **`peer_data` (과거 합격생 성적 테이블)**
  - 주요 컬럼: `student_name`, `univ`, `department`(`일반인문`, `일반자연`, `학사인문`, `학사자연`), `major`, `year`

### 2. 코드로 직접 수정해야 할 4가지 핵심 요구사항

#### ① 모집요강 엑셀 업로드 로직 개선 (백엔드)
- 엑셀(`DB업로드용` 시트: `대학`, `계열`, `학과명`, `일반정원`, `학사정원`) 업로드 시 **`일반정원 == 0`이고 `학사정원 == 0`인 행도 건너뛰지 말고 반드시 DB에 저장**되도록 해 줘.
- 업로드한 대학(`univ`)의 기존 `year = 2026` 모집요강 데이터가 있다면 깔끔하게 교체(Clean Overwrite)되도록 처리해 줘.
- **업로드 완료 직후 서버 메모리의 `DEPT_CACHE`를 즉시 초기화하거나 DB에서 다시 로드**해서, 사용자가 임의로 원서를 담았다가 삭제하지 않아도 프론트엔드에 새 대학·학과가 바로 반영되게 해 줘.

#### ② `peer_data` ↔ `recruit_quota` 자동 매칭 정규화 함수 고도화 (백엔드)
- 현재 대학명(`univ`) + 전형/계열(`department`) + 학과명(`major`)을 비교해 과거 합격생을 연결할 때, 아래 케이스 때문에 매칭이 끊기는 문제가 있어. **양쪽(`peer_data.major`와 `recruit_quota.major`) 모두 동일한 정규화 함수**를 거치도록 수정해 줘.
  1. **앞쪽 학부명 접두어 제거**: `전자공학부 나노·반도체전공`, `첨단소재·전자융합공학부 신소재물리전공`, `Fine Arts학부 서양화전공`처럼 앞에 `~학부 `가 붙어 있으면 `^.+?학부\s+(.+)` 패턴으로 제거해 줘. (단, 단독 형태인 `법학부`, `경영학부` 등은 유지)
  2. **끝부분 접미어 일관 제거**: `시스템생명공학과` ↔ `시스템생명공학전공`, `컴퓨터공학전공` ↔ `컴퓨터공학과`가 서로 매칭되도록 끝의 `(학전공|공학전공|공학과|학과|학부|전공|과)`를 제거한 핵심 키워드로 비교해 줘.
  3. **특수기호 및 공백 무시**: `*`, `·`, `•`, `ㆍ`, `(`, `)`, `[`, `]`, `/`, `-`, 공백 제거 후 비교해 줘.

#### ③ 현행 미선발 / 개편 과거 학과(`0명 / 0명`) UI 자동 분리 (프론트엔드 Vue)
- `general_quota === 0 && bachelor_quota === 0`인 학과는 `DEPT_CACHE` 매칭과 대학 전체 합격생 통계에서는 **절대 제외하지 말고 그대로 포함**시켜 줘.
- 단, 화면(Vue)에서 모집단위 목록을 보여줄 때는 두 그룹으로 자동 분리해 줘:
  - **상단 `[2027 모집학과]`**: `general_quota > 0 || bachelor_quota > 0`인 학과만 표시 (기존처럼 원서 담기 가능).
  - **하단 `[현행 미선발 / 개편 과거 학과 (과거 합격생 이력)]`**: `general_quota === 0 && bachelor_quota === 0`인 학과들을 구분선 아래 접이식 패널에 따로 모아서 표시. 과거 합격생 성적 조회는 가능하되 **원서 담기(지원) 버튼은 비활성화**해 줘.

#### ④ 디버깅용 매칭 점검 진단 API 추가 (백엔드)
- 특정 대학(`univ`)을 전달하면 `peer_data` 중 매칭에 실패한 학생(`student_name`, `department`, `major`, `year`) 목록을 바로 확인할 수 있는 진단 엔드포인트(`/api/quota/unmatched-diagnosis`)를 추가해 줘.

### 3. 작업 진행 방식
1. 먼저 관련 백엔드(FastAPI)와 프론트엔드(Vue) 파일을 검색해서 **어떤 파일의 어느 함수를 어떻게 수정할지 계획**을 간단히 보여줘.
2. 내가 확인하면 기존 파일에 직접 코드를 수정해 줘. (새 테스트 파일이나 백업 파일은 생성하지 마.)
```

## 3. 새 채팅방용 모집요강 분석 프롬프트

> 새로운 채팅방에서 다음 대학의 **2027학년도 편입학 모집요강 PDF**를 첨부하면서 첫 메시지로 붙여넣는 프롬프트입니다.

```text
나는 편입 상담 웹앱(`Peer Score Finder`)을 운영하고 있어. 앞으로 내가 업로드하는 대학별 **2027학년도 편입학 모집요강 PDF**를 분석해서, DB(`recruit_quota`) 업로드용 엑셀 파일과 과거 합격생(`peer_data`) 매칭용 SQL을 만들어 줘.

지금까지 한국항공대, 가천대, 숙명여대, 건국대학교(서울), 경기대, 국민대 작업을 마쳤고, 아래 규칙을 반드시 지켜서 결과물을 만들어 줘.

### 1. DB 구조 및 자동 매칭 규칙 (중요)
- **모집요강 테이블 (`recruit_quota`)**:
  - 주요 컬럼: `year`(현재 DB 기준 `2026`으로 적재), `univ`, `department`, `major`, `general_quota`, `bachelor_quota`
  - **0명 학과 유지**: 일반·학사 정원이 모두 0명인 미모집·특별전형 전용 학과도 과거 데이터 연결 및 UI 분리를 위해 누락하지 말고 포함해 줘.
- **과거 합격생 테이블 (`peer_data`)**:
  - 주요 컬럼: `student_name`, `univ`, `department`(`일반인문`, `일반자연`, `학사인문`, `학사자연`), `major`, `year`
- **백엔드 자동 매칭 방식**:
  - `univ` 일치 + `department`(전형+계열) 일치 + 학과명 정규화(앞쪽 `~학부 ` 접두어 제거, 특수기호 제거, 끝부분 `(학전공|공학전공|공학과|학과|학부|전공|과)` 제거 후 핵심 키워드 비교) 방식으로 연결됨.
  - 따라서 학과명이 완전히 다른 이름으로 개편되었거나(예: `나노전자물리학과` → `양자융합공학과`), 계열(`인문`/`자연`)이 오기입된 과거 데이터만 보정해 주면 됨.

### 2. 모집요강 PDF 업로드 시 필수 출력물 4가지

#### ① 엑셀 파일 생성 (`.xlsx`)
- **1번 시트 (`DB업로드용`)**:
  - 컬럼 순서(5개 고정): `대학`, `계열`, `학과명`, `일반정원`, `학사정원`
  - `계열`은 반드시 **`인문`** 또는 **`자연`**으로만 표기 (예체능·사범 등 기타 계열은 시험과목 및 시스템 규격에 맞춰 `인문` 또는 `자연`으로 분류).
  - 파이썬 코드로 일반정원·학사정원 합계가 PDF 총계표와 100% 일치하는지 검증 후 생성해 줘.
- **2번 시트 (`전형상세_참고표`)**:
  - 컬럼: `단과대학`, `계열`(요강 원문 계열), `학과명`, `전형방법(시험과목)`, `일반정원`, `학사정원`, `특별전형(농어촌/기회균등/특성화 등)`, `비고(캠퍼스, 동일계열 제한, 우선선발, 수료학점 차등 등)`

#### ② 2027학년도 모집단위 및 전형 변동 핵심 요약
- 전년 대비 변경사항, 미모집(0명) 학과, 계열 함정(예: 인문계열인데 자연명칭이거나, 자연계열인데 수학 없이 영어 100%로 선발하는 학과), 일반편입 수료학점 차등 기준, 다년제 이수 조건 등을 정리하고 단과대·계열별 모집인원 총계 표를 보여줘.

#### ③ `[학점은행제 지원자격]` 박스 복사·붙여넣기용 요약
- 일반편입(전문학사 및 학사과정 이수학점 기준), 학사편입, 특별전형 자격을 코드블록 텍스트로 깔끔하게 정리해 줘.

#### ④ DB 반영 및 과거 합격생 연결 SQL 세트
1. **기존 모집요강 초기화 SQL**: `DELETE FROM recruit_quota WHERE year = 2026 AND univ = '대학명';`
2. **과거 합격생(`peer_data`) 점검 및 매핑 SQL**:
   - 기존 `univ`, `department`, `major` 분포 조회 쿼리
   - 개편 전 구(舊) 학과명 → 2027 현행 모집단위명 `UPDATE` 쿼리 및 계열 오기입 보정 쿼리
3. **매칭 누락 여부 최종 검증 SQL**: `peer_data`와 `recruit_quota`를 `LEFT JOIN`하여 `✅ 연결됨` / `❌ 매칭실패`를 한눈에 확인하는 조회 쿼리.

위 규칙을 숙지했으면, 지금 첨부한 모집요강 PDF부터 바로 분석해서 진행해 줘!
```
